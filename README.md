# inhCHAT

Локальный веб-клиент для OpenAI-compatible LLM: обычный чат, работа с файлами,
история в SQLite и пошаговый «Режим работы». Сервер на Flask, интерфейс на
HTML/CSS/JS. Поддерживаются **Windows, Linux и macOS**.

## Установка

Нужен **Python 3.10+**. Для обычного чата с собственным OpenAI-compatible API
этого достаточно. Для дополнительного локального прокси **FreeDeepseekAPI**
нужны Git, Node.js и npm. Прокси необязателен.

Скачайте проект, затем запустите команды из папки проекта:

**Windows (PowerShell или cmd):**

```powershell
py -3 setup.py
py -3 start.py
```

Если Python установлен без `py`, используйте `python setup.py` и
`python start.py`. Можно также открыть `setup.bat` и `start.bat`.

**Linux / macOS:**

```bash
python3 setup.py
python3 start.py
```

Или `./setup.sh` и `./start.sh` (при необходимости выдайте `chmod +x`).
На Linux для создания виртуального окружения может понадобиться пакет
`python3-venv` из менеджера пакетов вашего дистрибутива.

Если FreeDeepseekAPI не нужен, быстрая установка без Node.js и Git:

```bash
python3 setup.py --skip-deepseek
```

На Windows вместо `python3` используйте `py -3` или `python`.

После запуска откройте **http://127.0.0.1:6767**.

### Первый вход

`users.json` создаётся при установке, если отсутствует:

```json
[
  {"username": "admin", "password": "676769"}
]
```

**Немедленно смените пароль перед использованием.** Регистрации из браузера
нет, пользователей редактирует администратор через `users.json`.
Учётные данные в этом файле хранятся открытым текстом; приложение
рассчитано на доверенный локальный компьютер, не публикуйте порт 6767 в интернет.

Файл `.env` также создаётся при первой установке и содержит уникальный
`APP_SECRET_KEY`. Существующие `.env` и `users.json` не перезаписываются.

## Потоковые ответы

Обычный чат и текстовые этапы «Режима работы» теперь используют
OpenAI-compatible `stream: true`: сервер читает SSE от провайдера и
передаёт дельты клиенту по **NDJSON**. Ответ появляется сразу по мере
поступления частей, без ожидания всего текста. Поддерживается кириллица,
ошибки провайдера и прерывание запроса при переключении обычного чата.

Если API игнорирует `stream: true` и возвращает обычный JSON,
клиент получит текст целиком, потому что провайдер физически не стримит.
Подготовка строгого отчёта DOCX/PDF требует полной генерации до отдачи
готовых документов. Планы задач также формируются полностью перед разбором.

Прежний JSON-контракт `POST /api/chats/<id>/message` сохранён.
Новый поток: `POST /api/chats/<id>/message?stream=1`
с `Content-Type: application/x-ndjson`; события
`delta`, `done`, `error`. Тот же `?stream=1` доступен для
`/api/work/task/<id>` и для текстового `/api/work/final/<id>`.

## Подключение моделей

Настройки → Провайдеры:

```text
Название: Мой API
Base URL: https://api.openai.com/v1
Модель: <нужная модель>
API key: <ключ>
```

Можно добавить и локальные OpenAI-compatible серверы. Ключ сохраняется
в локальной SQLite-базе. Сервер может автоматически получить список моделей
с `GET /models`.

## FreeDeepseekAPI

Если Git и Node.js/npm установлены, `setup.py` пытается установить
FreeDeepseekAPI в `.vendor/FreeDeepseekAPI`. Если они отсутствуют, обычный
чат продолжает работать.

После установки откройте в интерфейсе **Настройки → DeepSeek →
Войти в DeepSeek**. При следующих запусках `start.py` поднимает прокси,
если обнаружен `deepseek-auth.json`.

Данные авторизации DeepSeek и API-ключи не публикуйте. Не загружайте
`data/`, `workspace/`, `.vendor/`, `users.json` или `.env` в Git.

## Режим работы

В этом режиме модель сначала строит план, затем выполняет задачи по этапам,
работает с материалами из чата и общей библиотеки и готовит итоговый ответ.
Можно создавать файлы и архивы внутри `workspace/`. Строгое форматирование
позволяет генерировать DOCX/PDF. Этапы могут занимать время, даже когда
текстовые результаты передаются потоково.

## Файлы

- `server.py`: активный Flask-сервер и API чатов.
- `run_server.py`: точка входа серверной части и повторные попытки для обычных вызовов.
- `llm_streaming.py`: читатель SSE и NDJSON-события.
- `work_routes.py`, `workmode.py`, `work_recovery.py`: режим работы.
- `provider_service.py`: конфигурация OpenAI-compatible API.
- `static/`: интерфейс.
- `platform_utils.py`: запуск npm на Windows/Linux.
- `setup.py`, `start.py`: кроссплатформенная установка и запуск.
- `setup.bat`, `start.bat`: запуск двойным щелчком в Windows.
- `setup.sh`, `start.sh`: удобные оболочки для Linux/macOS.
- `app.py`: **устаревший альтернативный прототип**, не используется при нормальном запуске.

## Тестирование

```bash
python -m unittest discover -v
node --check static/app.js
```

Автоматические тесты проверяют разбор SSE, fallback для обычного JSON,
обработку UTF-8 и поведение URL провайдера. Тестирование на самих
платформах с реальным LLM-провайдером остаётся отдельным интеграционным шагом.

## Безопасность и ограничения

Приложение по умолчанию слушает только `127.0.0.1:6767` и предназначено
для локальной работы. Пароли хранятся в конфиге открытым текстом; не
используйте здесь пароли от других сервисов. Нельзя считать текущую схему
аутентификации и загрузки файлов безопасной для публичного доступа.
Новые ответы сохраняются в историю только после успешного завершения
потока. Старый механизм ответа целиком сохранён для совместимости.
